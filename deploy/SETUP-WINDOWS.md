# راه‌اندازی روی VPS ویندوزی — قدم‌به‌قدم

این راهنما ربات را از صفر روی یک VPS ویندوزی بالا می‌آورد و اگر نسخه‌ای از
قبل جایی در حال اجراست، جایگزینش می‌کند بدون اینکه چیزی از دست برود.

**پیش از هر کاری این دو نکته را بخوانید:**

> ⚠️ **دو نسخه‌ی همزمان با یک توکن با هم می‌جنگند.** تلگرام اجازه نمی‌دهد دو
> پروسه همزمان از یک `BOT_TOKEN` پیام بگیرند؛ هر دو مدام قطع و وصل می‌شوند و
> پیام‌ها گم می‌گردند. پس **اول نسخه‌ی قدیمی را خاموش کنید، بعد نسخه‌ی تازه را
> روشن.** هیچ‌وقت هر دو با هم نه.

> ⚠️ **اگر دیتابیس قدیمی را می‌آورید، `FERNET_KEY` هم باید همان قبلی باشد.**
> سشن کاربران با این کلید رمزنگاری شده؛ با کلید تازه، دیتابیس سالم می‌ماند ولی
> هیچ اکانتی باز نمی‌شود و همه باید دوباره وارد شوند.

---

## بخش ۰ — اول از نسخه‌ی قدیمی پشتیبان بگیرید

روی **همان دستگاهی که ربات الان رویش اجرا می‌شود** (سیستم خودتان):

```bat
.\backup.bat
```

یک فایل `telkap-backup-<تاریخ>.zip` کنار پروژه ساخته می‌شود که شامل پوشه‌ی
`data` (دیتابیس، سشن‌ها، پشتیبان‌های قبلی) و فایل `.env` است.

این zip را جایی امن نگه دارید — داخلش کلیدهای شماست.

اگر `backup.bat` را ندارید (نسخه‌ی قدیمی است)، دستی این دو را کپی کنید:

```
data\          ← کل پوشه
.env           ← فایل تنظیمات
```

> استفاده کنید. این مرحله تنها جایی است که به اینترنت آزاد نیاز دارد.

## بخش ۲ — پر کردن `.env`

فایل `C:\Telegramcopybot\.env` را با Notepad باز کنید.

### مقادیری که حتماً باید پر شوند

| متغیر | از کجا |
|---|---|
| `BOT_TOKEN` | [@BotFather](https://t.me/BotFather) → `/newbot` |
| `API_ID` و `API_HASH` | [my.telegram.org/apps](https://my.telegram.org/apps) |
| `FERNET_KEY` | دستور پایین |
| `ADMIN_IDS` | آیدی عددی خودتان (از [@userinfobot](https://t.me/userinfobot)) |
| `BOT_USERNAME` | نام کاربری ربات، بدون `@` |

ساخت `FERNET_KEY`:

```bat
.venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

> ⚠️ **اگر دیتابیس قدیمی را می‌آورید، این دستور را نزنید.** به‌جایش
> `FERNET_KEY` را از `.env` قدیمی بردارید و همان را بگذارید. کلید تازه یعنی
> همه‌ی سشن‌های ذخیره‌شده بی‌فایده می‌شوند.

> 🔒 هیچ‌کدام از این چهار مقدار (`BOT_TOKEN`، `API_ID`، `API_HASH`،
> `FERNET_KEY`) را در چت، تیکت، یا هیچ جای عمومی نفرستید. فقط داخل `.env` روی
> سرور بمانند.

### مقادیری که خوب است پر کنید

| متغیر | چرا |
|---|---|
| `CARD_NUMBER` و `CARD_HOLDER` | تا کاربر بتواند کارت‌به‌کارت بزند و رسید بفرستد. خالی بماند، به پشتیبانی ارجاع داده می‌شود |
| `SUPPORT_USERNAME` | آیدی پشتیبانی که در ربات نشان داده می‌شود |
| `TIMEZONE_OFFSET` | برای ایران `3.5` |
| `TRIAL_DAYS` | روزهای اشتراک رایگان اولیه (`0` = بدون) |

### پروکسی

اگر VPS به `api.telegram.org` دسترسی مستقیم ندارد:

```
PROXY_URL=socks5://127.0.0.1:10808
```

اگر VPN سرور حالت TUN/Global دارد، این را خالی بگذارید.

برای اینکه بفهمید کدام حالت است، این را بزنید:

```bat
.\nettest.bat
```

چهار چیز را جدا تست می‌کند و در آخر می‌گوید مشکل کجاست:

| تست | اگر رد شود یعنی |
|---|---|
| تبدیل نام `api.telegram.org` | DNS سرور کار نمی‌کند — روی `1.1.1.1` بگذاریدش |
| اتصال مستقیم به `api.telegram.org:443` | ربات بدون پروکسی بالا نمی‌آید |
| مرکز داده‌های تلگرام | «اتصال اکانت» کار نمی‌کند حتی اگر خودِ ربات بالا بیاید |
| خودِ پروکسیِ داخل `.env` | برنامه‌ی پروکسی روی سرور روشن نیست یا پورتش فرق دارد |

اگر پروکسی از نوع `socks` است، این دو را هم نصب کنید:

```bat
.venv\Scripts\pip install aiohttp-socks python-socks
```

#### `socks5` یا `socks5h`؟

اگر `nettest` گفت تبدیل نام **جواب جعلی** می‌دهد — یعنی `api.telegram.org`
به آدرسی مثل `10.10.34.35` تبدیل شده — حتماً `socks5h` بنویسید:

```
PROXY_URL=socks5h://127.0.0.1:10808
```

تفاوتش این است که با `socks5` نام را خودِ سرور تبدیل می‌کند و باز به همان
آدرس جعلی می‌رسد؛ با `socks5h` تبدیل نام هم از داخل پروکسی رد می‌شود.
این تک حرف `h` تفاوت بین «کار می‌کند» و «باز هم وصل نمی‌شود» است.

## بخش ۳ — آوردن دیتابیس قدیمی (اختیاری)

**اگر ربات قبلی کاربر واقعی داشته** و می‌خواهید اشتراک‌ها و تنظیماتشان بماند:

1. مطمئن شوید ربات قدیمی **خاموش** است (پنجره‌اش را ببندید یا سرویسش را
   `stop` کنید).
2. فایل zip پشتیبان را روی VPS باز کنید.
3. پوشه‌ی `data` را داخل `C:\Telegramcopybot\` بگذارید (اگر از قبل `data` هست،
   جایگزینش کنید).
4. `FERNET_KEY` را از `.env` قدیمی در `.env` تازه بگذارید.

**اگر ربات قبلی فقط تست بوده** و داده‌ی ارزشمندی ندارد، این بخش را رد کنید —
دیتابیس تازه در اولین اجرا خودش ساخته می‌شود.

> جدول‌های تازه و ستون‌های تازه خودکار به دیتابیس قدیمی اضافه می‌شوند. لازم
> نیست کاری بکنید و چیزی از داده‌های قبلی پاک نمی‌شود.

## بخش ۴ — تست اولیه

```bat
.\run.bat
```

چند ثانیه صبر کنید. باید لاگ راه‌اندازی را ببینید و خطایی نباشد.

حالا در تلگرام به ربات `/start` بزنید. اگر منوی اصلی آمد، همه‌چیز درست است.

با `Ctrl+C` ببندیدش — این فقط تست بود.

### اگر بالا نیامد

| پیام | معنی |
|---|---|
| `متغیرهای محیطی زیر تنظیم نشده‌اند` | یکی از چهار مقدار اجباری در `.env` خالی است |
| `Unauthorized` | `BOT_TOKEN` غلط است |
| `Conflict: terminated by other getUpdates` | یک نسخه‌ی دیگر با همین توکن جایی روشن است — پیدایش کنید و خاموشش کنید |
| `Cannot connect to host api.telegram.org` | شبکه به تلگرام دسترسی ندارد؛ `.\nettest.bat` را بزنید و طبق خروجی‌اش `PROXY_URL` را تنظیم کنید |

## بخش ۵ — سرویس دائمی با NSSM

تا وقتی پنجره‌ی `run.bat` باز است ربات روشن است — با بستن پنجره یا خروج از
Remote Desktop خاموش می‌شود. برای ۲۴ ساعته ماندن باید سرویس ویندوز بسازید.

### ۵.۱ نصب NSSM

[nssm.cc/download](https://nssm.cc/download) را بگیرید، از حالت zip دربیاورید
و `nssm.exe` (نسخه‌ی `win64`) را در `C:\nssm\` بگذارید.

### ۵.۲ ساخت سرویس

Command Prompt را **با دسترسی Administrator** باز کنید:

```bat
C:\nssm\nssm.exe install TelkapBot
```

در پنجره‌ای که باز می‌شود:

**تب Application**

| فیلد | مقدار |
|---|---|
| Path | `C:\Telegramcopybot\.venv\Scripts\python.exe` |
| Startup directory | `C:\Telegramcopybot` |
| Arguments | `-m telkap.main` |

**تب I/O** — تا لاگ‌ها جایی بمانند و بشود عیب را پیدا کرد:

| فیلد | مقدار |
|---|---|
| Output (stdout) | `C:\Telegramcopybot\data\bot.log` |
| Error (stderr) | `C:\Telegramcopybot\data\bot.log` |

**تب Exit actions**

| فیلد | مقدار |
|---|---|
| Restart | انتخاب شود |
| Delay | `10000` (میلی‌ثانیه) |

بعد `Install service` را بزنید.

### ۵.۳ روشن کردن

```bat
nssm start TelkapBot
nssm status TelkapBot
```

باید `SERVICE_RUNNING` بدهد.

سرویس روی `Automatic` است، پس با ری‌استارت شدن VPS خودش بالا می‌آید و لازم
نیست کسی وارد ویندوز شود.

### دستورهای روزمره

```bat
nssm start TelkapBot        rem روشن کردن
nssm stop TelkapBot         rem خاموش کردن
nssm restart TelkapBot      rem بعد از هر به‌روزرسانی
nssm status TelkapBot       rem وضعیت
```

دیدن لاگ زنده:

```bat
powershell -Command "Get-Content C:\Telegramcopybot\data\bot.log -Wait -Tail 50"
```

حالا که نسخه‌ی VPS بالاست، نسخه‌ی روی سیستم خودتان را کامل خاموش کنید:

- اگر با `run.bat` اجرا می‌شد → پنجره را ببندید
- اگر سرویس بود → `nssm stop TelkapBot` و بعد `nssm remove TelkapBot confirm`

اگر یادتان برود، هر دو نسخه سر یک توکن دعوا می‌کنند و ربات بی‌ثبات می‌شود.

## بخش ۷ — پشتیبان‌گیری بیرون از سرور

پشتیبان محلی به‌تنهایی محافظت نیست: اگر VPS از دست برود، پشتیبان هم با آن
می‌رود.

1. در تلگرام یک **کانال خصوصی** بسازید
2. ربات را در آن **ادمین** کنید
3. در ربات: `⚙️ سیستم` → `🆔 گرفتن شناسه‌ی کانال`
4. یک پیام از آن کانال به ربات فوروارد کنید
5. دکمه‌ی «همین را کانال پشتیبان کن» را بزنید

از این به بعد هر `BACKUP_HOURS` ساعت (پیش‌فرض ۱۲) یک نسخه‌ی فشرده خودکار به
آن کانال می‌رود. بدون هزینه، بدون سرویس اضافه، و بیرون از دسترس هر اتفاقی که
برای VPS بیفتد.

## بخش ۷.۵ — پنل وب (اختیاری)

پنل داخل همان پروسه‌ی ربات بالا می‌آید. نه نصب تازه‌ای دارد، نه سرویس دوم، نه
دیتابیس جدا. پیش‌فرض خاموش است.

### ۷.۵.۱ رکورد DNS

در cPanel یک رکورد A بسازید:

| نام | نوع | مقدار |
|---|---|---|
| `botpanel` | A | `194.5.195.93` |

### ۷.۵.۲ روشن کردن در `.env`

```
WEB_ENABLED=true
WEB_HOST=127.0.0.1
WEB_PORT=8080
WEB_BASE_URL=https://botpanel.softmiliac.com
```

سپس `nssm restart TelkapBot`.

> `WEB_HOST=127.0.0.1` یعنی پنل فقط از خود سرور در دسترس است. بخش بعدی یک
> وب‌سرور جلویش می‌گذارد که HTTPS را می‌رساند. **این را روی `0.0.0.0` نگذارید
> مگر اینکه HTTPS داشته باشید** — بدون آن، کوکی ورود لخت روی شبکه می‌رود.

### ۷.۵.۳ HTTPS با Caddy

روی ویندوز، ساده‌ترین راهِ گرفتن گواهی، Caddy است: یک فایل exe که خودش از
Let's Encrypt گواهی می‌گیرد و تمدیدش هم می‌کند.

۱. از [caddyserver.com/download](https://caddyserver.com/download) نسخه‌ی
   ویندوز را بگیرید و `caddy.exe` را در `C:\caddy\` بگذارید.

۲. فایل `C:\caddy\Caddyfile` را بسازید (بدون پسوند):

```
botpanel.softmiliac.com {
    reverse_proxy 127.0.0.1:8080
}
```

۳. در فایروال ویندوز پورت‌های **۸۰** و **۴۴۳** را باز کنید. پورت ۸۰ برای
   گرفتن گواهی لازم است، حتی اگر پنل فقط روی ۴۴۳ باز شود.

۴. تست:

```bat
cd C:\caddy
caddy run
```

اگر گواهی گرفته شد، `https://botpanel.softmiliac.com` باید صفحه‌ی ورود پنل را
نشان دهد. با `Ctrl+C` ببندید.

۵. سرویس دائمی، مثل خود ربات:

```bat
C:\nssm\nssm.exe install Caddy
```

- **Path**: `C:\caddy\caddy.exe`
- **Startup directory**: `C:\caddy`
- **Arguments**: `run`
- تب **Exit actions** → `Restart`

```bat
nssm start Caddy
```

### ۷.۵.۴ ورود

در ربات: `⚙️ سیستم` → `🖥 پنل وب`. یک لینک می‌گیرید که **۵ دقیقه** اعتبار
دارد و با اولین باز شدن می‌سوزد.

رمز عبوری در کار نیست — هویت شما را همان چت تلگرام تأیید کرده. اگر لینک را
برای کسی بفرستید، او با نام شما وارد می‌شود.

### ۷.۵.۵ اگر ورود در حلقه افتاد

لینک را باز می‌کنید، به صفحه‌ی ورود برمی‌گردید، بدون هیچ خطایی. یعنی
`WEB_BASE_URL` روی `https://` است ولی شما دارید از `http://` باز می‌کنید؛
کوکی `Secure` است و مرورگر برش نمی‌گرداند.

در `data\bot.log` هشدارش نوشته می‌شود. یا HTTPS را راه بیندازید، یا
`WEB_BASE_URL` را همان آدرسی بگذارید که واقعاً باز می‌کنید.

## بخش ۸ — به‌روزرسانی در آینده

هر بار که نسخه‌ی تازه‌ای آمد:

```bat
cd C:\Telegramcopybot

.\backup.bat                  rem ۱. اول پشتیبان
nssm stop TelkapBot         rem ۲. خاموش کردن
.\update.bat                  rem ۳. گرفتن نسخه‌ی تازه
nssm start TelkapBot        rem ۴. روشن کردن دوباره
```

`update.bat` دستور `git reset --hard origin/main` می‌زند. این یعنی **هر
تغییری که دستی در فایل‌های پروژه داده باشید پاک می‌شود** — ولی `.env` و پوشه‌ی
`data` دست‌نخورده می‌مانند، چون در `.gitignore` هستند.

### کلیدهای تازه‌ی `.env`

هر نسخه ممکن است تنظیمات تازه‌ای بیاورد. چون `.env` شما به‌روز نمی‌شود،
آن کلیدها در فایلتان نیستند.

**این مشکلی ایجاد نمی‌کند** — هر کلید تازه مقدار پیش‌فرض دارد و ربات با
`.env` قدیمی هم بالا می‌آید. فقط چهار کلید اجباری‌اند: `BOT_TOKEN`،
`API_ID`، `API_HASH` و `FERNET_KEY`.

ولی وقتی بخواهید قابلیت تازه‌ای را روشن کنید، باید کلیدش را داشته باشید.
به‌جای مقایسه‌ی دستی:

```bat
.\envsync.bat            rem فقط بگو چه چیزی کم است
.\envsync.bat --apply    rem اضافه‌شان کن
```

کلیدهای نبوده را با توضیح‌شان ته `.env` اضافه می‌کند، **بدون دست زدن به
مقادیر شما**، و پیش از نوشتن یک پشتیبان `.env.bak-…` می‌گذارد.

> ⚠️ هرگز `.env.example` را روی `.env` کپی نکنید — توکن و `FERNET_KEY`
> را از دست می‌دهید، و بدون `FERNET_KEY` قدیمی همه‌ی سشن‌های کاربران
> غیرقابل بازگشایی می‌شوند.

## مشکلات رایج

**`'setup.bat' is not recognized` با اینکه فایل آنجاست**

**همیشه `.\` را جلوی نام بگذارید:**

```bat
.\setup.bat
```

ویندوز سرور معمولاً `NoDefaultCurrentDirectoryInExePath` را روشن دارد؛ این
تنظیم امنیتی جلوی جستجوی پوشه‌ی جاری را می‌گیرد، پس `setup.bat` پیدا
نمی‌شود ولی `.\setup.bat` می‌شود. پیام خطا این را نمی‌گوید و آدم را دنبال
مشکل PATH می‌فرستد.

اگر با `.\` هم نشد، این سه را ببینید:

```bat
dir *.bat
echo %PATHEXT%
set NoDefaultCurrentDirectory
```

اولی می‌گوید فایل‌ها آنجا هستند یا نه، دومی باید `.BAT` را داشته باشد، و
سومی همان تنظیم امنیتی را نشان می‌دهد.

**`Windows cannot find '.bat'`**
`start` یک دستور داخلی خودِ ویندوز است، پس `start.bat` به‌صورت
`start .bat` خوانده می‌شد. به همین دلیل نامش به `run.bat` تغییر کرد. اگر
نسخه‌ی قدیمی را دارید، `.\start.bat` بزنید یا پروژه را دوباره بگیرید.


**ربات بعد از ری‌استارت VPS بالا نمی‌آید**
سرویس روی `Automatic` نیست. در `services.msc` سرویس `TelkapBot` را پیدا کنید
و `Startup type` را روی `Automatic` بگذارید.

**`SERVICE_PAUSED` یا مدام ری‌استارت می‌شود**
`data\bot.log` را ببینید. تقریباً همیشه یا `.env` ناقص است یا شبکه به تلگرام
نمی‌رسد.

**کاربران می‌گویند اکانتشان قطع شده**
اگر دیتابیس را آورده‌اید ولی `FERNET_KEY` عوض شده، دقیقاً همین اتفاق می‌افتد.
کلید قدیمی را برگردانید.

**فضای دیسک پر شده**
`data\backups\` و `data\downloads\` را نگاه کنید. ربات ۱۴ نسخه‌ی پشتیبان آخر
را نگه می‌دارد؛ اگر دیتابیس بزرگ شده، `LOG_RETENTION_DAYS` را در `.env` کمتر
کنید (جدول گزارش فعالیت سریع‌ترین بخش رشد است).
