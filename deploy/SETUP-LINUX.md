# راه‌اندازی روی سرور خارجی (اوبونتو) — قدم‌به‌قدم

این راهنما برای وقتی است که ربات را روی یک VPS **خارج از ایران** می‌برید.

**چرا؟** روی سرور ایران، تلگرام مسدود است و ربات باید از یک تونل رد شود.
هر چیزی که آن تونل را بخواباند — منقضی شدن کانفیگ، به‌روزرسانی برنامه‌ی
پروکسی، خطای درایور TUN — ربات مشتری‌های شما را هم می‌خواباند، و شما
معمولاً وقتی می‌فهمید که مشتری شکایت کند.

روی سرور خارجی این کل دسته مشکل وجود ندارد: `PROXY_URL` خالی می‌ماند.

---

## معماری پیشنهادی

از هر دو سروری که دارید استفاده می‌شود، هرکدام برای کاری که در آن بهتر است:

| کجا | چه چیزی | چرا |
|---|---|---|
| **VPS خارجی** | ربات + پنل مدیریت | به تلگرام دسترسی مستقیم دارد |
| **هاست ایران (cPanel)** | صفحه‌ی فروش (`site/index.html`) | برای بازدیدکننده‌ی ایرانی سریع است و HTML ساده است |

**بخش پرداخت جدا لازم ندارد.** پرداخت کارت‌به‌کارت کاملاً داخل تلگرام
انجام می‌شود: کاربر طرح را می‌زند، شماره کارت را می‌بیند، رسید را در همان
چت می‌فرستد و ادمین با یک دکمه تأیید می‌کند. هیچ‌کدام از این‌ها به IP
ایران نیاز ندارد.

## بخش ۱ — سرور

هر ارائه‌دهنده‌ای که IP خارج از ایران بدهد. کمترین مشخصات کافی:

| | حداقل | راحت |
|---|---|---|
| RAM | ۱ گیگ | ۲ گیگ |
| CPU | ۱ هسته | ۲ هسته |
| دیسک | ۲۰ گیگ | ۴۰ گیگ |
| سیستم | Ubuntu 24.04 | همان |

**کدام سیستم عامل؟** اگر فهرست انتخاب داشت، **`ubuntu24`** را بزنید.
پایتون ۳٫۱۲ دارد که درست وسط چیزی است که CI ما می‌سنجد (۳٫۱۱ و ۳٫۱۳)، و
تا ۲۰۲۹ پشتیبانی می‌شود.

| گزینه | نظر |
|---|---|
| `ubuntu24` | ✅ انتخاب درست |
| `debian12` / `debian13` | کار می‌کنند، ولی راهنما برای اوبونتو نوشته شده |
| `ubuntu26` | تازه است؛ پایتونش را هنوز نسنجیده‌ایم، ریسک بی‌دلیل |
| `almalinux9` | ❌ پایتون پیش‌فرضش ۳٫۹ است و ما ۳٫۱۱ به بالا می‌خواهیم |

> **مکان سرور مهم است.** آلمان، هلند و فنلاند به ایران نزدیک‌ترند و
> تأخیر کمتری دارند. آمریکا کار می‌کند ولی کندتر است.

**درباره‌ی ترافیک نگران نباشید.** در حالت عادی رسانه‌ها اصلاً از سرور شما
رد نمی‌شوند: شناسه‌ی فایل به تلگرام داده می‌شود و خودش همان فایل را در
مقصد می‌گذارد. یک ویدیوی ۵۰۰ مگابایتی هم چند کیلوبایت ترافیک می‌برد.

فقط دو حالت فایل را واقعاً دانلود و دوباره آپلود می‌کنند:

- **واترمارک** — عکس باید پردازش شود، پس دانلود و آپلود می‌شود
- **بازنویسی نام کانفیگ در فایل پیوست** — به همان دلیل

هر دو سهمیه‌دار و اختیاری‌اند، پس ترافیک با تعداد پست بالا نمی‌رود؛ با
تعداد واترمارک بالا می‌رود. ۱ ترابایت برای شروع زیاد هم هست.

**درباره‌ی CPU:** تنها کار سنگینِ پردازنده واترمارک زدن روی عکس است.
یک هسته برای شروع کافی است؛ اگر روزی واترمارک پرمصرف شد، ارتقای هسته
ساده است.

پس از تحویل، با SSH وارد شوید:

```bash
ssh root@<آی‌پی-سرور>
```

## بخش ۲ — آماده‌سازی

```bash
apt update && apt upgrade -y
apt install -y python3 python3-venv python3-pip git ufw

python3 --version      # باید ۳٫۱۱ یا بالاتر باشد
```

یک کاربر جدا برای ربات بسازید — ربات نباید با `root` اجرا شود:

```bash
adduser --system --group --home /opt/telkap telkap
```

## بخش ۴ — آوردن تنظیمات و دیتابیس قدیمی

**این مهم‌ترین قدم است.** اگر ربات قبلاً کاربر واقعی داشته، `.env` و پوشه‌ی
`data` را از دستگاه قبلی بیاورید.

### ⚠️ هرگز `.env.example` را روی `.env` کپی نکنید

با این کار `FERNET_KEY` عوض می‌شود، و آن کلید چیزی است که سشن اکانت
کاربران با آن رمز شده. با کلید تازه **هیچ‌کدام از اکانت‌های متصل باز
نمی‌شوند** و همه باید از نو وارد شوند.

### روی دستگاه قدیمی

ربات را خاموش کنید، بعد:

```bat
.\backup.bat
```

یک فایل `telkap-backup-<تاریخ>.zip` می‌سازد که هم `.env` و هم `data` را دارد.

### انتقال به سرور تازه

از همان دستگاه قدیمی:

```bat
scp telkap-backup-*.zip root@<آی‌پی-سرور>:/opt/telkap/
```

روی سرور:

```bash
cd /opt/telkap
apt install -y unzip
unzip telkap-backup-*.zip
rm telkap-backup-*.zip          # فایل کلیدها را روی سرور نگذارید
```

### اگر ربات قبلی کاربری نداشته

`.env` را از نو بسازید:

```bash
cp .env.example .env
nano .env
```

و `FERNET_KEY` تازه بسازید:

```bash
.venv/bin/python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

### تغییرات لازم در `.env`

```
PROXY_URL=
```

**خالی.** دیگر تونلی در کار نیست — این تمام دلیل جابه‌جایی بود.

اگر پنل وب می‌خواهید:

```
WEB_ENABLED=true
WEB_HOST=127.0.0.1
WEB_PORT=8080
WEB_BASE_URL=https://botpanel.softmiliac.com
```

مالکیت فایل‌ها را درست کنید:

```bash
chown -R telkap:telkap /opt/telkap
chmod 600 /opt/telkap/.env
```

## بخش ۵ — تست اولیه

پیش از سرویس کردن، یک بار دستی اجرا کنید:

```bash
cd /opt/telkap
.venv/bin/python tools/nettest.py
```

روی سرور خارجی باید ببینید:

```
۲) اتصال مستقیم به api.telegram.org:443 باز است؟
  [✓] پورت باز شد
  [✓] سرور تلگرام پاسخ داد (یعنی دسترسی هست)
```

بعد خود ربات:

```bash
.venv/bin/python -m telkap.main
```

منتظر `ربات @… آماده است` بمانید و در تلگرام `/start` بدهید. با `Ctrl+C`
متوقفش کنید.

## بخش ۶ — سرویس دائمی

تا اینجا ربات با بستن SSH می‌میرد. با systemd دائمی می‌شود:

```bash
cp /opt/telkap/deploy/telkap.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now telkap
```

بررسی:

```bash
systemctl status telkap
journalctl -u telkap -f          # لاگ زنده، خروج با Ctrl+C
```

از این پس ربات با ری‌استارت سرور خودش بالا می‌آید و اگر کرش کند ۱۰ ثانیه
بعد دوباره اجرا می‌شود.

دستورهای روزمره:

```bash
systemctl restart telkap        # بعد از هر به‌روزرسانی
systemctl stop telkap
systemctl start telkap
```

## بخش ۷ — پنل وب روی دامنه با HTTPS

پنل روی `127.0.0.1:8080` است، یعنی از بیرون در دسترس نیست. یک وب‌سرور
جلویش می‌گذاریم که HTTPS را هم خودش می‌گیرد.

**اول دامنه را به IP سرور تازه ببرید.** در cPanel، رکورد A را برای
`botpanel.softmiliac.com` روی IP جدید بگذارید و منتظر بمانید تا پخش شود.

بعد Caddy را نصب کنید — گواهی HTTPS را خودکار می‌گیرد و تمدید می‌کند:

```bash
apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy
```

فایل تنظیماتش:

```bash
nano /etc/caddy/Caddyfile
```

محتوا — فقط همین سه خط:

```
botpanel.softmiliac.com {
    reverse_proxy 127.0.0.1:8080
}
```

```bash
systemctl reload caddy
```

حالا `https://botpanel.softmiliac.com` باز می‌شود.

> **چرا HTTPS اجباری است:** کوکی ورود پنل با پرچم `Secure` فرستاده می‌شود.
> روی `http` مرورگر آن را نگه نمی‌دارد و شما در حلقه‌ی ورود گیر می‌کنید،
> بدون هیچ پیام خطایی.

### درگاه زرین‌پال (اختیاری)

درگاه به همین دامنه وابسته است، پس اگر می‌خواهیدش، حالا وقتش است.

۱. در `.env` کد پذیرنده را بگذارید و مطمئن شوید `WEB_BASE_URL` پر است:

```
ZARINPAL_MERCHANT=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
WEB_BASE_URL=https://botpanel.softmiliac.com
```

۲. **در پنل زرین‌پال، نشانی بازگشت را ثبت کنید:**

```
https://botpanel.softmiliac.com/pay/zarinpal
```

> این قدم را جا نیندازید. بدون ثبت این نشانی، کاربر پرداخت می‌کند ولی
> برنمی‌گردد و اشتراکش فعال نمی‌شود — و هیچ خطایی هم در لاگ ربات نمی‌بینید،
> چون اصلاً درخواستی به سرور شما نمی‌رسد.

۳. `systemctl restart telkap`

۴. **یک خرید آزمایشی با کمترین پلن بزنید.** این تنها راه اطمینان است، و
   یک نکته‌ی ناشناخته را هم روشن می‌کند: آیا زرین‌پال از IP سرور خارجی
   درخواست می‌پذیرد؟ اگر نپذیرفت، در لاگ خواهید دید:

```bash
journalctl -u telkap -n 50 | grep -i zarinpal
```

### دیوار آتش

```bash
ufw allow OpenSSH
ufw allow 80,443/tcp
ufw --force enable
```

پورت ۸۰۸۰ را باز نکنید؛ فقط Caddy باید به آن برسد.

## بخش ۸ — پشتیبان‌گیری

ربات خودش هر ۱۲ ساعت از دیتابیس نسخه می‌گیرد. ولی نسخه‌ی روی همان سرور،
اگر سرور از دست برود، با آن می‌رود.

در ربات: **⚙️ سیستم ← 🆔 گرفتن شناسه‌ی کانال**. یک کانال خصوصی بسازید،
ربات را در آن ادمین کنید، یک پیام از کانال فوروارد کنید و «همین را کانال
پشتیبان کن» را بزنید. از آن پس هر نسخه به آن کانال هم می‌رود.

## بخش ۹ — به‌روزرسانی در آینده

**یک دستور، هر بار:**

```bash
sudo bash /opt/telkap/deploy/update.sh
```

همین. دفعه‌ی اول که این فایل روی سرور نیست، یک بار `git pull` بزنید تا
بیاید.

اسکریپت این کارها را می‌کند:

| گام | چه می‌کند | چرا مهم است |
|---|---|---|
| ۱ | از دیتابیس پشتیبان می‌گیرد (`data/backups/`) | سشن ورود همه‌ی کاربران آنجاست |
| ۲ | کد را از `main` می‌گیرد | — |
| ۳ | کتابخانه‌های تازه را نصب می‌کند | نسخه‌ی جدید ممکن است کتابخانه‌ی تازه بخواهد |
| ۴ | کلیدهای تازه‌ی `.env` را گزارش می‌دهد | بدون این، قابلیت جدید بی‌صدا خاموش می‌ماند |
| ۵ | ربات را روشن و **چک می‌کند واقعاً بالا آمده** | `start` بی‌خطا بودن یعنی «شروع شد»، نه «کار می‌کند» |
| ۶ | اگر بالا نیامد، **خودش به نسخه‌ی قبلی برمی‌گردد** | بدترین حالت چند ثانیه قطعی است، نه یک شب بیداری |

اگر برگشت اتفاق افتاد، اسکریپت ۲۵ خط آخر لاگ را چاپ می‌کند — همان را
برای من بفرستید.

**`.env` هرگز دست نمی‌خورد.** `FERNET_KEY` داخل آن است و اگر برود، سشن
همه‌ی کاربران غیرقابل رمزگشایی می‌شود و همه باید دوباره وارد شوند.

<details>
<summary>همان کار به‌صورت دستی</summary>

```bash
cd /opt/telkap
systemctl stop telkap
sudo -u telkap git pull origin main
sudo -u telkap .venv/bin/pip install -r requirements.txt
sudo -u telkap .venv/bin/python tools/envsync.py            # چه چیزی کم است
sudo -u telkap .venv/bin/python tools/envsync.py --apply    # اضافه‌شان کن
systemctl start telkap
systemctl status telkap
```

## بخش ۱۰ — خاموش کردن نسخه‌ی قدیمی

**تا وقتی مطمئن نشده‌اید نسخه‌ی تازه کار می‌کند این کار را نکنید.**

دو ربات با یک توکن همزمان کار نمی‌کنند: تلگرام `getUpdates` را فقط به یکی
می‌دهد و آن دو مدام همدیگر را قطع می‌کنند.

روی ویندوز سرور قدیمی:

```bat
nssm stop TelkapBot
nssm remove TelkapBot confirm
```

یا اگر سرویس نشده بود، فقط پنجره‌ی `run.bat` را ببندید.

## مشکلات رایج

| نشانه | علت |
|---|---|
| `Conflict: terminated by other getUpdates` | نسخه‌ی قدیمی هنوز روشن است؛ خاموشش کنید |
| `متغیرهای محیطی تنظیم نشده‌اند` | `.env` نیامده یا مالکیتش اشتباه است |
| ربات بالا می‌آید ولی اکانت‌ها وصل نمی‌شوند | `FERNET_KEY` با نسخه‌ی قدیمی یکی نیست |
| پنل باز می‌شود ولی مدام به صفحه‌ی ورود برمی‌گردد | با `http` باز کرده‌اید؛ `https` لازم است |
| `502 Bad Gateway` از Caddy | ربات بالا نیست — `systemctl status telkap` |
| صفحه اصلاً باز نمی‌شود | رکورد A هنوز پخش نشده، یا `ufw` بسته است |
